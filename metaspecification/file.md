# File organization

## Scope and size

- Keep each file focused on one topic.
- Aim for no more than 100 lines. Count every line, including blank lines, tables, and code blocks.
- Review longer files for a useful split. Keep content together when splitting would hurt clarity.
- Move a complete subtopic into a clearly named file in the same directory.

## Line length

- Keep lines within 100 characters, counting spaces, indentation, and Markdown syntax.
  Allow longer URLs, identifiers, or code only when shortening or wrapping would break them.
- Shorten long points before wrapping them. Do not squeeze formatting or omit needed details
  just to meet a limit.

## Requirements and formatting

- Write one requirement per bullet or short paragraph. Keep its conditions and exceptions beside it.
- Put requirements before supporting reasons and examples.
- Headings are optional. The filename and opening content should make the topic clear.
- Use only the sections needed. No introduction, summary, or fixed layout is required.
- Follow [style](style.md) for Markdown formatting.
